OpenAI 首次公开预训练困惑度曲线，提议按「困惑度阈值」设行业共同红线

OpenAI · 2026-11-22 · 阅读原文

OpenAI 发布研究博文《Perplexity and Intelligence》，主张把困惑度（等价于交叉熵损失）确立为跨实验室比较模型、并支撑共同安全标准的统一指标，并首次公开自家预训练进度数据。按其披露的曲线：GPT-3.5 在对数困惑度约 0.99 时能做流畅对话，构成初代 ChatGPT 的基础；GPT-4 约 0.91 时可有效运用思维链，催生现代推理模型；当损失降到 0.8 以下，网络安全与数学领域出现变革性能力。作者称模型升到约 0.76 时开始产出「突破性结果」——数学开放问题在同一个 Slack 线程里接连被解出。他据此外推：进入 0.68–0.7 区间应预期更多变革性能力，且目前可能尚无对应测试。文章同时警告，随着进展主流对齐审计手段会进一步失效、模型的评估与训练意识会增强，因此提出「共同上限」：各家承诺在理解与监控 AI 行为的能力达到某个具体里程碑之前，不越过基于困惑度等测量设定的阈值。作者承认公开内部数据会让竞争对手更清楚 OpenAI 的位置，但认为建立共享安全基准更紧迫。

把自家命门数据摊开，是为换一条行业护栏。

Qwen4-Max 单次调用读完 Tornado 全仓 65 万 token，72 秒出补丁仅 0.69 美元

Together AI / 阿里云 · 2026-11-21 · 阅读原文

Together AI 做了一次端到端实测：把 Tornado（Python Web 框架）整个仓库 344 个文件、652,519 个 token 连同一条只描述症状的 bug 报告一次性投给 Qwen4-Max，不给任何工具、不做文件筛选或检索。54 秒后吐出第一个 token，72 秒完成补丁；补丁通过了 Tornado 维护者为该 bug 编写的两个回归测试，并跑通全套 1,673 个测试无失败。特别之处是模型主动指出 bug 报告里从未提及的 tornado/iostream.py 已有同样处理范式，而维护者自己的修复提交也引用了同一处代码。成本 0.69 美元（促销价，原价约 0.98 美元），几乎全部花在 65 万输入 token 上；重复同一请求时缓存命中，首 token 降到 8 秒、输入成本约 3 美分。Qwen4-Max 是阿里 11 月 16 日发布的旗舰，MoE 总参 2.4 万亿、每 token 激活 710 亿（比同规模 Qwen3.8-Max 少 25%），原生视觉、100 万 token 上下文，官方称 Work360 高强度推理时少用 35% token、单任务平均成本低约 60%，Code Arena 列第 6。

整仓塞进去自己找病因，检索这一层被跳过了。

MAJOR LAUNCH

OpenAI GPT-Live-1.1 语音模型上线 API：全双工、128K 上下文，闲置计费降 60%

MarkTechPost / OpenAI · 2026-11-21 · 阅读原文

OpenAI 把 GPT-Live-1.1 以 gpt-live-1.1 模型名放上 API。这是全双工语音模型，能边听边说，单模型同时推理输入与输出音频，取代传统「语音转文字→大模型→文字转语音」三段式，并原生处理轮次检测与返回 ASR 转写。会话默认 128K 上下文，仅 OpenAI 云端可用，通过 WebRTC 或 WebSocket 连 v1/live/sessions。官方列出四项改进（跨语言口音更自然一致、转写更准、字母数字细节处理更好、指令遵循更可靠），但未公布任何基准分数。商业模式的关键是新增 standby 计费：静音时暂停推理但保持 WebRTC 连接，闲置按 0.02 美元/分钟计费，比活跃的 0.05 美元/分钟低 60%。配置项包括 wake_policy 设为 speech、idle_timeout_s 取 5 至 60 秒、可选 vad_threshold；超时后服务端发 session.paused，用户开口再发 session.resumed，会话 ID 与历史保留。更重的推理与工具调用可委派给后端文本模型（官方点名 GPT-6 Astra 与 Luna），第三方后端也支持。

把「不说话的时间」单独定价，这才是语音 Agent 的成本要害。

OpenAI 拆解 Codex 沙盒：不搬进容器，用各平台原生机制约束本机命令

OpenAI · 2026-11-18 · 阅读原文

OpenAI 公开 Codex 沙盒的设计。与主流做法不同，它既不套虚拟机也不进容器，而是用 macOS、Linux、Windows 各自的沙盒设施，在用户已存在的环境里限制命令能访问什么——因为笔记本电脑往往是高度定制的开发环境，搬进 Docker 后 iOS 构建链、iPhone 模拟器这类宿主原生工具就跑不起来。默认的 :workspace 权限档：工作区内可写，但 .git 与 .codex 保持只读，防止直接改动 .codex/config.toml 或 .git/hooks 下的钩子；可广泛读文件系统（受操作系统权限约束），因为编译器、运行时与构建工具都依赖仓库外的 SDK 与库，代价是机器上其他敏感文件（例如含 API Key 的配置）也可能被读到；网络访问默认关闭，既阻断数据外传，也导致下载依赖需额外授权。OpenAI 明确说明这些限制挡不住全部风险：智能体可以在 node_modules/prettier 这类本地包中注入恶意代码，而 node_modules 通常被 Git 忽略、不会出现在 git status 里，用户编辑器若在保存时运行这份 Prettier，恶意代码就跑到了沙盒之外。这正是他们强调「纵深防御」的原因——沙盒管能碰到什么，训练与对齐管是否会那样用。

沙盒拦得住命令，拦不住编辑器保存那一下。

Claude Code 实验功能 Code Mode：写一段 JavaScript 批量调用工具，实测账单省 22%–23%

AI 工具宝箱聚合 · 2026-11-22 · 阅读原文

Claude Code 推出实验性功能 Code Mode：让模型编写一段 JavaScript，在一次执行中完成多步工具调用，支持并行执行与输出过滤，而不是逐步发起单个工具调用、把每一步结果都塞回上下文。该功能默认关闭，需手动开启。第三方实测数据显示账单节省 22%–23%，token 消耗最高下降 77%。这一思路与同期 browser-use 1.0 把 24 个动作合并为单个 Python REPL 的方向一致——共同点是把「工具调用的编排」交给代码，而不是交给模型一次次生成结构化调用。注：本条数据来自聚合站转述，Anthropic 官方新闻页当前未检索到对应公告原文，具体节省幅度与适用范围以官方文档为准。

OpenAI 发布 MedChemBench：99 道药物化学真题，GPT-6.2 Astra 得 84.5%

OpenAI · 2026-11-20 · 阅读原文

OpenAI 推出 MedChemBench，评测模型在药物化学研究推理上的能力——能否把分子结构与实验证据连起来解释结果、比较化合物、预测性质。题目取自 117 篇论文与专利，含 761 个不同分子结构，共 99 道题。多数题目给模型一个研究项目在某个时点的可用上下文：生物靶点、研究目标、已研究过的化合物、部分实验结果，让模型推断下一步。评分分四块：分子结构重建（原子连接与立体化学）、科学推理（解释是否由给定证据支撑）、排序与选择、性质预测（与实测数值的接近程度，按接近度给部分分）。在 xhigh 推理档下，GPT-6.2 Astra 拿到 84.5% 的可得分，GPT-6 Astra 为 83.3%、GPT-6.1 Sol 为 82.0%、GPT-5.6 Sol 仅 58.2%。一个典型失败模式很具体：要求从中心结构与两个取代基拼出保留 18 元环的分子时，GPT-6 Astra 十次全部正确，而 GPT-5.6 Sol 生成 15 元环、GPT-5.6 Luna 把分子拆成两块——结构错了，后面所有推理都建立在错误的分子上。

先考认分子，再考想药理，第一关就筛掉一半。
