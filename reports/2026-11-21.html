Claude 协助证明黎曼猜想，Lean 与 Mathlib 社区认证代码正确

Lean/Mathlib 联合声明 · Nature · 2026-11-21 · 阅读原文

11 月 20 日，Anthropic 数学家 Levent Alpöge（哈佛休假的数论学者）在个人网站发布 4 页说明，称与 Claude 在约六周内证明了黎曼猜想，方法还可延伸到广义黎曼猜想。他以 Lean 库形式提交证明，代码达 1700 万行。11 月 21 日下午，Lean FRO 与 Mathlib Initiative 发布联合声明：「我们完全相信 Alpöge 的黎曼猜想证明是正确的。」认证分四项：陈述本身即 Mathlib 中经专家审定的 RiemannHypothesis；库可无误编译，数十人复现了相同的原始证明导出文件；社区用 comparator 与 con-leche 两套独立工具确认所证定理与 Mathlib 陈述完全一致；导出证明通过 Lean 官方内核、con-leche、con-ron 及多个第三方检查器验证，其中 con-leche 与 con-ron 自带相对集合论的「无法接受假证明」形式化证明。需分清两点：这是 Lean 层面的形式化验证，不等于数学界已完成对思路的理解与审阅；牛津 James Maynard 称若完全成立「显然是数学史上的里程碑」，蒙特利尔 Andrew Granville 则批评 4 页说明写得「混乱」，并质疑发布时点。同日另有意大利数学家 Alessandro Masullo 的纯人工证明预印本发布。

代码过了机器审，但数学界还没读懂它。

MiniMax 内部模型自动破解密码学：McEliece 挑战解出 55 个未解实例，最高加速 4.3 万倍

MiniMax · 2026-11-20 · 阅读原文

MiniMax 研究团队用内部专用模型 MIM 做自动化密码分析，在三个方向取得结果。一是在 NIST 标准化竞赛候选算法上做出首个实用破解：Waterfall-256（SHA-3 候选）单核 0.045 秒构造出碰撞，Blender-256 单核 0.36–2.3 秒找到全轮碰撞，后量子候选 LOCKER 把求解矩阵从 42 PB 压缩至 58 MB 并在 2 秒内恢复共享密钥，ROLLO-I-128 约 6 秒从公钥恢复等价私钥。二是对近年密码学会议论文与竞赛获奖设计实现密文伪造或密钥恢复。三是在底层数学难题上解出数十个此前未解的高阶实例，相对此前最优求解器实测加速数百至数万倍；McEliece 挑战解出 55 个未解实例，最高加速约 4.3 万倍。研究强调密码分析结果二元且可验证——脚本要么恢复目标秘密要么没有，不给幻觉留空间，因此适合作长程推理的测试场。

答案非对即错，这是最干净的模型能力考卷。

METR 更新能力评估：任务时间视野翻倍周期 3.61 个月，可验证子集仅 1.65 个月

METR · 2026-11-20 · 阅读原文

METR 发布 2026 年第四季度能力评估更新，覆盖至 Opus 5.5 与 GPT-6 Astra 共 15 个模型。核心结论：合并 TH1.1 与 TH2 套件后，任务时间视野的翻倍周期为 3.61 个月；而 TH2 的可验证子集仅 1.65 个月，说明改进速度在不同任务类型上并不均匀。在自建人类基线中，招募的专家通常无法超越当前前沿模型；但在已有 10 名以上领域专家尝试的任务上，模型多处于很高分位而非绝对第一。研究还发现，模型在难以转化为 RL 训练环境（以「生命周期成本」衡量）的任务上表现较差——成本翻倍大致相当于时间视野减半的难度惩罚，但高低成本子集的改进速率相近。报告同时指出一处相反结论：在缺乏清晰实证反馈、需要判断力的任务上，AI 智能体判断力弱于人类专家。METR 明确表示：现有公开证据不足以排除未来两年出现剧烈的 AI 研发加速。

考卷上赢、考卷外输，分界线决定能替代谁。

Thinking Machines 开源 Inkling 2 Mini：循环 Transformer，约 20GB 可在笔记本离线跑

Thinking Machines Lab · 2026-11-20 · 阅读原文

Thinking Machines Lab 发布 Inkling 2 Mini，采用循环 Transformer 架构：24 层中中间 12 层对每个 token 连续跑三次，使模型在不写长推理的情况下内部多推理，用更少 token 得到答案。模型为 MoE，总参数 26.4B、激活 3.4B、含循环后每 token 权重激活 5.4B；支持文本与图像输入、100 万 token 上下文、Apache 2.0 许可。在总参数 100B 以下的开放权重模型中，其 DeepSWE v1.1 得 48.2%、Vals Index v2.2 得 46.5%，均列第一。权重多以 NVFP4 训练与部署、最后四层为 MXFP8，总内存占用约 20GB，可在消费级笔记本运行——研究员在航班上用一台 M5 Pro/48GB 的 MacBook Pro 离线几分钟内建出可玩飞行模拟器。研究称更大循环次数可提升无 CoT 的时间视野（1 次 16 秒→3 次 37 秒），思维链变短但保持可读，智能体破坏性测试未随循环数上升。

把推理塞进循环，省的是 token，赌的是可监控性。

browser-use 1.0 把 24 个动作砍成 1 个 Python REPL：同模型得分升 14–33 分，成本降至 1/5.2

Browser Use · 2026-11-10 · 阅读原文

browser-use 发布 1.0，用一个 python 主工具取代 0.x 的 24 个浏览器动作：这是一个常驻 REPL，预导入 browser-harness 助手与裸 Chrome DevTools Protocol 调用 cdp()，模型直接写代码操作浏览器，另保留两种收尾方式。发布删除了 136,905 行、新增 29,601 行，554 个文件中 178 个 Python 文件合并为 43 个。在 BU Bench v2.1 上，同样三个模型比 0.x 得分高 14–33 分、成本低 2.7–5.2 倍；团队明确说明这是整版发布的整体效果、每模型仅跑一次，不能全归功于工具变更。观察 199 条运行轨迹（12,976 次代码调用、约 47 个不同 CDP 命令）显示，模型会自行调用未被封装的能力，例如用 Page.stopLoading 解卡死页面、用 Network.getResponseBody 读取响应。作者回顾：最初每个 bug 都变成一个动作，峰值 29 个，而每个动作的 schema 都要占提示词，菜单外的需求就卡死。

工具越多越笨，这条教训终于被写成代码。

OpenHands 把 CVE 修复交给智能体流水线：镜像 critical 从 87 降到 5，high 从 1997 降到 188

OpenHands · 2026-11-19 · 阅读原文

OpenHands 公开其 CVE 修复自动化流程：10 月新披露 CVE 达 17,050 个（约每天 550 个），接近去年同期的四倍，为有记录以来最高月份。他们把大部分修复交给智能体工作流——由智能体挑选修复、开 PR、合并低风险项并跟踪每个修复直至部署，人类每天读一条 Slack 消息、审几个 PR。效果上，其镜像的可修复 critical 漏洞从 87 个降到 5 个，high 从 1997 个降到 188 个。方法上有两个关键点：一是交付物清单不能手工维护（每次扫描时从 Helm charts 渲染生成，覆盖可能部署的全部镜像）；二是至少用两套扫描器交叉（Trivy 与 Grype 在旧镜像上分别报 630 与 743 个漏洞，仅 462 个重叠）。作者认为至少 80% 的 CVE 修复工作可交给自主智能体，因为「计数下降且没坏」是少数没有争议的验收标准。

漏洞数量涨了四倍，人已经追不上了。
